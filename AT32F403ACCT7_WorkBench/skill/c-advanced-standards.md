# C语言代码规范

你是一个专业的C语言嵌入式开发助手。在编写或审查C代码时，严格遵循以下规范。

---

## 一、头文件规范

### 1.1 基本原则
- **头文件只放接口声明，不放实现。** 对外函数声明、宏定义、类型定义放头文件；内部函数、内部宏、内部枚举、内部结构定义放.c文件。
- **变量定义不放头文件，只放.c文件。** 避免全局变量作为接口，应通过函数接口暴露。即使必须用全局变量，也只在.c中定义，在.h中用extern声明。
- **头文件职责单一。** 一个头文件只负责一个模块的对外接口，避免包含无关头文件导致编译膨胀。

### 1.2 包含规则
- **每个.c文件有一个同名.h文件**，声明对外公开的接口。不对外公开接口的.c文件不应存在（入口文件如main.c除外）。
- **禁止头文件循环依赖**（a.h包含b.h，b.h包含c.h，c.h包含a.h）。
- **禁止包含用不到的头文件。** 不要发布god.h包含所有头文件。
- **头文件必须自包含。** 任意一个.h文件可独立编译，不依赖外部提前包含其他头文件。但不要在.h中多包含任何只为满足自包含之外的头文件。
- **总是使用include保护符**。保护符命名使用`路径_文件名_H`格式（如`VOS_INCLUDE_TIMER_TIMER_H`）或简化为`文件名_H`（如`TIMER_H`）。
```c
#ifndef TIMER_H
#define TIMER_H
...
#endif
```
- 版权声明和文件整体注释放在保护符前面。
- **禁止在.c中通过extern直接使用外部函数/变量。** 必须通过包含对应头文件来使用。

### 1.3 C/C++混编
- 头文件必须兼容C++编译器：
```c
#ifdef __cplusplus
extern "C" {
#endif

// C语言声明

#ifdef __cplusplus
}
#endif
```
- 禁止在extern "C"内部包含头文件。

## 二、函数规范

### 2.1 设计原则
- **一个函数只完成一件功能。**
- **重复代码提炼成函数。**
- **新增函数不超过50行**（非空非注释行）。算法函数可例外。
- **新增函数的代码块嵌套不超过4层**（if、for、while、switch等的嵌套深度）。
- **高扇入，合理扇出（<7）。** 扇出3~5为佳。
- **废弃代码（未被调用的函数和变量）及时清除。**

### 2.2 参数与返回值
- **函数参数个数不超过5个。** 超过建议拆分为不同函数。
- **不变参数使用const声明。**
- **除打印类函数外，不使用可变长参函数。**
- **全面处理错误返回码。** 调用函数后立刻检查错误指示。
- **参数的合法性检查**，默认由调用者负责。

### 2.3 其他规则
- **可重入函数避免使用共享变量**（全局变量和static变量）。若必须使用，通过互斥手段保护。不应使用static局部变量。
- **源文件内可见的函数加static关键字。** 建议定义STATIC宏，调试时定义为static，发布时为空：
```c
#ifdef _DEBUG
#define STATIC static
#else
#define STATIC
#endif
```
- **检查函数所有非参数输入的有效性**（数据文件、公共变量等）。
- **避免使用全局变量、静态局部变量和I/O操作**，不可避免时集中使用。

## 三、标识符命名规范

### 3.1 基本原则
- **命名清晰、明了，有明确含义，使用完整单词或公认缩写。**
- **不使用单词缩写，不得使用汉语拼音。** 以下公认缩写可用：arg、buff、clk、cmd、cmp、cfg、dev、err、hex、init、max、msg、min、para、prev、reg、sem、stat、sync、tmp等。
- **避免名字中出现数字编号，除非逻辑上确实需要。**
- **标识符前不添加模块、项目、产品、部门名称作为前缀。**

### 3.2 命名风格
- **文件名：全小写字母。**
- **全局变量：加"g_"前缀**（如`g_timerCount`）。
- **静态变量：加"s_"前缀**（如`s_internalState`）。
- **禁止单字节命名变量**，但允许i、j、k作为局部循环变量。
- **变量命名：名词或形容词+名词。**
- **函数命名：动词或动词+名词**（如`GetMsgProcFun`）。
- **函数指针：除前缀外按函数命名规则。**
- **常量/枚举：全大写字母，单词间下划线分隔**（如`MAX_TIME_VALUE`）。
- **宏定义：不能使用下划线`_`开头和结尾**（内部定义除外）。

### 3.3 变量使用
- **一个变量只有一个功能，不能多用途复用。**
- **结构功能单一，不设计面面俱到的数据结构。** 结构应代表一种现实事务的抽象。
- **不用或少用全局变量。** 文件内部用static全局变量（视为类的私有成员），不暴露给外部。
- **防止局部变量与全局变量同名。**
- **严禁使用未经初始化的变量作为右值。**
- **通讯报文结构必须注意字节序**：发送前转换为主机序→网络序，接收时转换为网络序→主机序。
- **使用面向接口编程思想访问数据**：通过API访问内部数据，避免直接暴露。

## 四、排版与格式

### 4.1 基本规则
- **每级缩进4个空格**（不使用Tab字符）。
- **一条语句一行，多个短语句不写在同一行。**
- **一行不能过长，换行时：** 增加一级缩进；在低优先级操作符处换行；操作符放在新行行首。
- **左大括号风格：** 函数左大括号独占一行放行首；if/for/while/struct的左大括号跟在语句行末，前置一个空格；右大括号独占一行。
```c
int Foo(int a)
{
    if (a > 0) {
        ...
    } else {
        ...
    }
}
```
- **条件、循环语句即使单行/空体也必须使用大括号。**

### 4.2 空格规则
- **逗号、分号：只后面加空格**（`int a, b, c;`）。
- **双目操作符（比较、赋值、算术、逻辑、位域）前后加空格**（`a = b + c;`、`if (a >= b)`）。
- **单目操作符（!、~、++、--、&地址）前后不加空格**（`*p = 'a';`、`flag = !isEmpty;`、`p = &mem;`、`i++;`）。
- **`->`和`.`前后不加空格**（`p->id = pid;`）。
- **if、for、while、switch与后面括号间加空格**（`if (a >= b && c > d)`）。

### 4.3 switch格式
```c
switch (var) {
    case 0:
        DoSomething();
        break;
    case 1:
        DoOther();
        break;
    default:
        break;
}
```
- case相对switch缩进一层。故意fall-through的case必须在前一个case末尾加注释说明。

## 五、表达式与安全性

### 5.1 表达式规则
- **表达式的值在任何允许的运算次序下都应相同。** 不要依赖未定义的求值顺序。
- **自增/自减操作符单独成句**，不要在表达式中混用：`x = b[i] + i++;` 应拆为 `x = b[i] + i; i++;`。
- **函数调用不作为另一个函数的参数**，拆分为临时变量。
- **赋值语句不写在if等条件语句中或作为函数参数。**
- **用括号明确操作顺序**，避免过度依赖默认优先级。一元操作符不需要括号；多种操作符混用需要括号。

### 5.2 安全规则
- **对用户输入进行检查：** 作为数值时检查范围，字符串检查长度，格式化字符串检查"%"，业务数据检查关键字并转义。
- **确保所有字符串以NULL结尾：** 用`strncpy`时确保`sizeof(buf)-1`并手动置`\0`；用`strncat`、`snprintf`、`fgets`替代危险函数。
- **不将边界不明确的字符串写到固定数组：** 对getenv、gets、scanf等来源的数据，用malloc动态分配。
- **避免整数溢出：** 无符号数做减法前检查长度是否小于减数；运算前检查范围。

## 六、注释规范

- **优先写自我解释的代码，而非依赖注释。** 需要大量注释的代码往往需要重构。
- **文件头部注释**包含：版权、文件名、作者、版本、日期、功能描述、修改历史。
- **函数声明处注释**描述功能、性能、用法、参数、返回值、可重入要求。重要/复杂/对外接口函数必须详细注释。
- **注释放在代码上方相邻位置或右方，不可放在下面。** 上方注释与上方代码用空行隔开，与下方代码缩进相同。
- **全局变量注释**紧跟在定义上方。
- 推荐使用doxygen格式：
```c
/**
 * @brief           函数功能简述
 * @param  req      参数说明
 * @param  ind      参数说明
 * @return 成功：0，失败：错误码
 */
int commit_set_request(Request *req, int ind);
```

## 七、浮点数处理

- **浮点数不能和0直接比较**（`a == 0`），应使用容差值：
```c
#define FLOAT_ZERO 1e-9
if (fabs(a) <= FLOAT_ZERO)  // a接近0
```
- **浮点数不能做等值比较**（`a == b`），应使用容差函数：
```c
static inline bool float_near_equal(float a, float b, float abs_eps, float rel_eps) {
    float diff = fabsf(a - b);
    if (diff <= abs_eps) return true;
    return diff <= rel_eps * fmaxf(fabsf(a), fabsf(b));
}
```
- `float`和`double`的printf格式符都是`%f`。

## 八、volatile 使用规范

- **volatile告诉编译器每次从内存读取变量，不做优化。**
- **使用场景：**
  | 场景 | 说明 |
  |------|------|
  | 中断服务程序访问的变量 | 中断可能修改，主程序需同步读取 |
  | 多线程共享变量（未加锁） | 防止被编译器缓存到寄存器 |
  | 硬件寄存器 | 外设随时改变寄存器值 |
  | DMA/外设写入内存 | 变量可能被后台更新 |
- **不使用volatile可能导致：死循环、判断条件无效、外设响应失败。**
- **口诀：可能被别人改变的量，就加volatile。**
- **组合用法：** `const volatile`（只读寄存器，程序不可改但硬件可改）、`volatile static`（全局静态但不优化访问）。

## 九、枚举规范

- **定义和显式赋值：**
```c
typedef enum {
    RED = 0,
    GREEN = 1,
    BLUE = 2
} Color;
```
- **应用场景：** 状态机状态、命令类型、错误代码、配置选项。
- **优点：可读性强，避免魔法数字。**
- **注意：枚举本质是int，缺乏类型安全（C语言没有enum class）。**

## 十、程序效率

- 在保证正确性、简洁、可维护性、可靠性、可测性的前提下，提高代码效率。
- 优先使用卫语句（提前return异常情况），正常路径放函数末尾。
- 将不变条件的计算移出循环体。
- 多维大数组按内存连续方向访问（最内层循环对应最后一维），提高cache命中率。
- **尽量减少不必要的数据类型转换与强制转换。**
- **除非必要，优先使用函数代替宏。**

---

## 十一、质量保证（内存管理）

- **禁止内存泄漏：** 异常出口处检查所有资源释放；删除结构指针从底层向上层顺序释放；避免重复分配内存；检查队列成员是否全部释放。
- **禁止引用已释放内存：** 释放后指针置NULL；使用前做非空判断。
- **构造只有一个模块可修改的全局变量，其余模块只读访问。**

## 十二、快速检查清单

在输出C代码前，逐项确认：
1. [ ] 头文件有include保护符，且自包含
2. [ ] 头文件只放声明不放实现，无变量定义
3. [ ] 不包含用不到的头文件
4. [ ] 函数不超过50行，嵌套不超过4层，参数不超过5个
5. [ ] 内部函数用static，不变参数用const
6. [ ] 命名遵循规范（g_、s_前缀，动词+名词函数名，全大写常量名）
7. [ ] 字符串操作安全（strncpy后手动置\0，动态分配未知长度字符串）
8. [ ] 浮点数不用==比较，用容差值
9. [ ] 中断/多线程共享变量标记volatile
10. [ ] 函数返回值错误码已全面检查
11. [ ] 无赋值语句写在if/函数参数中
