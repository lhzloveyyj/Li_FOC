1. 项目里的无感 FOC 总览

FOC 的目标是把三相电机变成“两个直流量”来控制：Id 负责磁链方向， 通常希望接近 0；Iq 负责转矩方向，主要决定电机出力。问题的核心在于： Park 变换必须知道转子电角度 θe。有感模式直接从 MT6701 编码器获得， 无感模式则由 SMO 滑模观测器和 PLL 锁相环估计。

2. FOC 数学原理：把交流电机变成直流控制对象

三相 PMSM 的电流是随角度变化的交流量，直接控制很难。FOC 的漂亮之处在于通过坐标变换， 把静止三相坐标 abc 先变成静止两相坐标 αβ，再变成随转子同步旋转的 dq 坐标。站在转子坐标系里看，理想稳态下 Id 和 Iq 就像直流量。

Clarke 变换：abc → αβ

Iα = Ia
Iβ = (Ia + 2Ib) / sqrt(3)　（常见形式，代码中按采样方向做了符号处理）

代码中调用 clarke_transform(-pFOC->Ia, -pFOC->Ib, ...)， 说明当前硬件采样方向与控制坐标定义相反，因此进入 Clarke 前做了取反。

Park 变换：αβ → dq

Id = Iα·cos(θe) + Iβ·sin(θe)
Iq = -Iα·sin(θe) + Iβ·cos(θe)

这里的 θe 是全系统最关键的输入。如果角度错了，原本应该产生转矩的 Iq 会被投影到错误方向，表现为无力、发热、震动甚至反转。

图 2：Park 变换相当于把坐标轴转到转子磁链上。

PMSM 在 dq 坐标下的直观模型

Ud = Rs·Id + Ld·dId/dt - ωe·Lq·Iq
Uq = Rs·Iq + Lq·dIq/dt + ωe·Ld·Id + ωe·ψf
Te ≈ 1.5·p·ψf·Iq　（表贴式 PMSM、Id≈0 时）

最后一个式子解释了为什么调试时总盯着 Iq：在 Id≈0 的策略下， Iq 几乎就是转矩旋钮。代码中 pFOC->ud = 0.000001f， 本质上就是希望 D 轴电流闭环把 Id 压在 0 附近。

逆 Park + SVPWM：把电压指令打回三相桥

Uα = -Uq·sin(θe) + Ud·cos(θe)
Uβ = Uq·cos(θe) + Ud·sin(θe)

inv_park_transform() 得到 Uα/Uβ 后，SVpwm() 判断参考电压矢量所在扇区，再用两个相邻基本矢量和零矢量合成目标电压。

图 3：SVPWM 的六扇区合成思路，对应 SVPWM.c 的 switch 分支。

3. SMO 滑模观测器：从电流误差“榨出”反电势

无感 FOC 的关键不是“猜角度”，而是先估计反电势。PMSM 旋转时，永磁体磁链切割定子绕组， 会在 αβ 坐标下产生一对正交反电势：

Eα = -ωe·ψf·sin(θe)
Eβ = ωe·ψf·cos(θe)
θe = atan2(-Eα, Eβ)

所以只要估出 Eα/Eβ，角度就能从 atan2 得到；项目进一步使用 PLL 让角度和速度更平滑。

按照参考文章的推导顺序重讲一遍

参考文章的讲法很有价值：它不是一上来就给代码，而是先问“观测器到底要观测什么”。 对 PMSM 无感 FOC 来说，我们真正缺的是转子电角度 θe；但 θe 并不能从静止电流里直接读出来，它藏在定子坐标系的反电势里。因此 SMO 的目标可以分成两步： 第一，用 uα/uβ 和 iα/iβ 重建反电势 Eα/Eβ； 第二，从这两个正交反电势信号中提取 θe 和 ωe。

第 1 层：uα/uβ + iα/iβ → 估计 Eα/Eβ
第 2 层：Eα/Eβ → atan2 或 PLL → θe / ωe
第 3 层：θe → Park / 逆 Park → FOC 闭环

本项目正是这个结构：FocContorl() 先得到 uAlpha/uBeta 和 iAlpha/iBeta，再调用 SMO_Update(&g_smoObserver, ...)。 SMO_Update() 内部估计 eAlpha/eBeta，然后把它们送入 PLL_Update()，最后输出 g_smoObserver.angle。

为什么观测器放在 αβ 坐标系，而不是 dq 坐标系

这是参考文章里很重要的一点。FOC 的电流环喜欢用 dq，因为 dq 下电流接近直流量，PI 好控；但无感观测器不能从 dq 开始设计。原因很简单： 要把电流从 αβ 变到 dq，本来就需要 θe。 如果观测器又基于一个估计出来的 θe 再去估计 θe， 那误差会在坐标变换和观测器之间互相喂回去。

所以更稳妥的办法是：观测器只吃定子坐标系里的真实可获得量，也就是 uα/uβ 和 iα/iβ。在你的代码里，这一点体现得很清楚： 

// FOC.c: 先由三相电流得到 iAlpha/iBeta，再用当前角度做 Park
clarke_transform(-pFOC->Ia, -pFOC->Ib, &pFOC->iAlpha, &pFOC->iBeta);
park_transform(pFOC->iAlpha, pFOC->iBeta, pFOC->correctedAngle,
               &pFOC->id, &pFOC->iq);

// 逆 Park 得到电压指令 uAlpha/uBeta
inv_park_transform(pFOC->uq, pFOC->ud, pFOC->correctedAngle,
                   &pFOC->uAlpha, &pFOC->uBeta);

// SMO 不吃 dq，它吃 αβ
SMO_Update(&g_smoObserver, pFOC->uAlpha, pFOC->uBeta,
           pFOC->iAlpha, pFOC->iBeta);

定子 αβ 坐标系下的电机方程

在 αβ 坐标系里，PMSM 的电流动态可以写成非常直观的形式： 电压减去电阻压降，再减去反电势，剩下的部分推动电感电流变化。

d iα / dt = (uα - Rs·iα - Eα) / Ls
d iβ / dt = (uβ - Rs·iβ - Eβ) / Ls

这里 uα/uβ 是我们给电机的电压，iα/iβ 是 ADC 测出来并 Clarke 变换后的电流，Rs/Ls 是电机模型参数。 唯一不好直接测的就是 Eα/Eβ。也正因为这个未知量卡在电流方程里， 我们可以反过来利用“电流模型预测值”和“实际电流测量值”的误差，把反电势逼出来。

从电机模型到观测器模型

如果真实电机满足上面的方程，那么我们可以在软件里复制一个“虚拟电机模型”： 给它同样的 uα/uβ，同样的 Rs/Ls，让它自己积分出一个估计电流 i_hat。如果模型完全准确且反电势已知，那么 i_hat 应该和真实电流 i 重合。问题是反电势未知，于是我们加入一个切换注入项 z，让它专门负责把估计电流拉回真实电流。

真实电机：di/dt = (u - Rs·i - E) / Ls
软件观测器：di_hat/dt = (u - Rs·i_hat - e_hat - z) / Ls
观测误差：s = i_hat - i

在本项目里，e_hat 是上一阶段滤波得到的反电势估计，z 是这一次根据电流误差算出的滑模注入量。注意代码使用的是 i_hat - i，因此注入项在观测器方程里写成 -z。

SMO 使用的电流模型

代码中的观测器状态是 iAlphaHat/iBetaHat，也就是“我认为当前电流应该是多少”。

err = i_hat - i_actual
z = k_slide · sat(err / band)
i_hat += Ts/Ls · (u - Rs·i_hat - e_hat - z)
e_hat += α · (z - e_hat)

如果估计电流和实际电流不一致，就说明模型里漏了东西。这个“漏掉的东西”主要就是反电势。 滑模注入量 z 会强行把电流估计误差拉回滑模面，之后再低通滤波得到 e_hat。

图 4：SMO 不是直接估角度，而是先通过滑模注入估计反电势。

滑模面是什么

在这个项目里，滑模面可以理解成电流估计误差为 0 的平面：

sα = iAlphaHat - iAlpha
sβ = iBetaHat - iBeta
滑模面：sα = 0 且 sβ = 0

观测器的目标不是让电机状态真的“停在某个物理平面上”，而是让估计误差状态被快速吸引到 s=0 附近。误差一旦围绕滑模面高频切换，注入量 z 的等效平均值就会逼近反电势。

融合参考文章后的一个关键澄清：

滑模面应该放在 iα/iβ 的电流误差平面来理解，而不是简单画成“误差-误差导数”的相图。 参考文章用实际电流和观测电流的差值构造滑模面；本项目代码使用 err = i_hat - i_actual，只是符号方向与常见写法相反，后续在电流观测方程中用 -z 注入，因此控制效果等价。

到达条件：为什么滑模增益必须压过反电势

参考文章用滑模控制的到达条件解释观测器能否收敛：如果取李雅普诺夫函数 V = 1/2·s²，希望误差能回到滑模面，就需要 dV/dt = s·ds/dt < 0。 换成电流观测器的直觉就是：误差在滑模面上方时，注入项要把它往下拉；误差在下方时，注入项要把它往上推。

s = i_hat - i
ds/dt ≈ (e_actual - e_hat - z) / Ls　（省略 Rs 误差项后的直观形式）
若 z 的幅值不足以覆盖 e_actual - e_hat，s·ds/dt 就可能变成正数，误差会离开滑模面
图 8：到达条件的物理含义：注入量要始终把误差推回滑模面。

等效控制思想：为什么 z 低通后就是反电势

参考文章的核心推导可以这样理解：滑模到达以后，误差 s 不再大幅远离 0，而是在滑模面附近快速切换。此时从低频平均意义上看， i_hat 和 i 的动态应该相同，也就是 di_hat/dt ≈ di/dt。把真实电机方程和观测器方程相减：

ds/dt = d(i_hat - i)/dt
ds/dt = [-Rs·(i_hat-i) + E - e_hat - z] / Ls
到达滑模面后：s≈0，ds/dt≈0
所以：z 的等效平均值 ≈ E - e_hat

如果一开始 e_hat 还没建立，那么 z 的低频成分主要就是反电势； 随着 e_hat 通过低通滤波逐渐跟上，观测器内部的电流模型也会越来越接近真实电机。 这就是为什么滑模观测器常常说“切换函数经过低通滤波得到反电势”。

本项目的实现比最基础形式多了一项 -e_hat，这样观测器不是完全靠 z 硬顶反电势，而是让低通后的 e_hat 也进入电流模型。 这会让电流观测模型更接近真实电机，同时降低注入项长期承担的负担。

图 9：滑模注入量高频抖动，低通后留下的低频等效量就是反电势估计。
为什么 k_slide 太小会高速抽搐？

反电势幅值近似 |E| = |ωe·ψf|，速度越高反电势越大。 但注入量被限制在 ±k_slide。如果 k_slide 小于需要补偿的反电势， 观测器就无法把误差拉回滑模面，e_hat 饱和，角度估计开始错误， FOC 转矩方向随之错乱。

图 10：k_slide 给的是观测器“最大纠偏能力”，太小会在高速先失锁。

滑模增益怎么理解：不是越大越好

参考文章在讲滑模增益时，核心意思可以概括成一句话：增益要大到足以保证到达条件， 但不能大到让切换抖振、噪声和滤波负担不可接受。对电机观测器而言， 需要被滑模项压住的主要扰动就是反电势，其次是电阻、电感参数误差、电压重构误差、采样噪声和死区误差。

k_slide 太小：注入量压不过反电势 → s 无法回到 0 → e_hat 饱和 → 角度失真
k_slide 适中：误差能快速回到滑模面 → z 的低频分量可用 → 反电势可估
k_slide 太大：z 高频抖振变重 → LPF 压力变大 → 角度噪声和电流噪声上升

这也解释了你之前遇到的“空载加速到某个点突然抽搐”：低速时反电势小， 即使 k_slide 偏小也暂时能工作；速度升高后，反电势幅值超过注入能力， 观测器先饱和，随后角度错误，最后 FOC 的转矩方向混乱。

为什么参考文章强调“抖振”

滑模控制的特点就是切换：误差在滑模面的一侧时给一个方向的注入， 到另一侧时给反方向的注入。理想数学模型里，开关可以无限快，系统会沿着滑模面运动； 但真实 MCU、ADC、电机和逆变器都有采样周期、量化误差、PWM 死区和噪声， 所以切换不会是理想无限频率，而会表现为可见的高频抖振。

对无感 FOC 来说，抖振的影响有三层：第一，zAlpha/zBeta 本身会很毛； 第二，低通滤波如果压不住，高频噪声会混进 eAlpha/eBeta； 第三，PLL 如果吃到带噪声的反电势，会把噪声变成角度和速度抖动，最终反过来影响 Park 变换。

本项目的工程处理：

代码没有使用硬 sign()，而是使用 smo_sat(err / band)。 这相当于给滑模面附近留出一个线性过渡区：误差很小时不马上打满 ±k_slide，从而减少抖振；误差足够大时仍然饱和到最大注入能力， 保留滑模观测器的强鲁棒性。

低通滤波的副作用：反电势变平滑，但角度会滞后

参考文章中也提到实际工程不能直接拿剧烈抖动的切换量当反电势，需要先滤波。 本项目用一阶低通 e += α·(z-e)，这样能把滑模高频抖振滤掉； 代价是反电势矢量在高速下产生相位滞后，所以代码又增加了相位补偿。

LPF 截止频率近似：fc ≈ α / (2π·Ts)
当前 α=0.02，Ts=50us，所以 fc ≈ 63.7Hz
相位补偿：phaseComp = atan(ω_hat·Ts / α)

这里的 fc 只是把离散一阶滤波器近似成连续低通后的直觉值。 真正调参时更应该看波形：如果 eAlpha/eBeta 像锯齿一样乱跳， 说明滤波太轻或滑模注入太硬；如果 rawAngle 明显落后编码器角， 或高速时电流角度偏差越来越大，说明滤波滞后需要补偿或提高滤波带宽。

本项目提供了几个遥测开关来观察这一点：CMD_SMO_BACKEMF 看 eAlpha/eBeta，CMD_SMO_RAW_ANGLE 看不经过 PLL 的反电势角， CMD_SMO_DIAG 看 eMag 和 pllError。 做学习汇报时，可以把这三个量当成“SMO 是否健康”的三根探针。

从反电势到角度：atan2 的符号关系

参考文章在得到反电势后，会用反电势和转子磁链之间的正交关系求角度。 对表贴式 PMSM，在 αβ 坐标系中可以把反电势写成：

Eα = -ωe·ψf·sin(θe)
Eβ = ωe·ψf·cos(θe)

如果电机正转，ωe 为正，反电势矢量比磁链矢量超前或滞后 90° 的关系由上式确定，因此可以用 atan2(-Eα, Eβ) 求磁链角。 反转时 ωe 符号会让反电势整体翻转 π，如果不处理，角度可能差半圈。 你的项目专门做了方向统一： 

bemfDir = SMO_GetElectricalDirectionSign(smo);
eAlphaFlux = bemfDir * smo->eAlpha;
eBetaFlux  = bemfDir * smo->eBeta;
smo->rawAngle = NormalizeAngle(atan2f(-eAlphaFlux, eBetaFlux));

这段代码的作用就是把“正转/反转导致的反电势极性翻转”先归一化，再从 Eα/Eβ 里提取磁链角。也就是说，本项目并不是盲目套 atan2，而是在工程上补了方向符号。

PLL 如何从反电势锁出角度

直接 atan2 可以得到原始角度，但速度差分很吵。PLL 的做法是维护一个内部角度 θ_hat，用反电势矢量和估计矢量的相位误差来修正它。

pllErr = -eα·cos(θ_hat) - eβ·sin(θ_hat)
pllErr_norm = pllErr / |E|
integral += Ki·pllErr_norm·Ts
ω_hat = Kp·pllErr_norm + integral
θ_hat += ω_hat·Ts

项目里还做了两件很实用的增强：第一，用 rawAngle 差分速度作为 PLL 速度前馈， 避免高速捕获时从 0 慢慢爬；第二，对反电势低通滤波造成的相位滞后做补偿。

phaseComp = gain · atan(ω_hat·Ts / e_lpf_alpha)
outputAngle = normalize(pll.theta + phaseComp)

把 PLL 当成二阶系统来理解

参考文章里提到 PLL 时，重点是它不是单纯滤波器，而是一个会“追相位”的闭环系统。 如果误差很小，sin(θ - θ_hat) 可以近似成 θ - θ_hat， PLL 的 PI 调节器就相当于给角度误差建立了一个二阶闭环：比例项决定当前误差修正速度， 积分项决定长期速度估计，二者一起决定带宽和阻尼。

小误差近似：pllErr ≈ θ_real - θ_hat
ω_hat = Kp·pllErr + ∫Ki·pllErr dt
θ_hat = ∫ω_hat dt

如果 Kp/Ki 太小，PLL 角度会落后，尤其在高速或加减速时跟不上； 如果太大，噪声会被放大，角度和速度会抖。你项目当前设置 FOC_SMO_PLL_KP = 800、FOC_SMO_PLL_KI = 80000， 这是偏高带宽的配置，目的就是让 PLL 能跟上低电感、高电角速度电机。

PLL 调参现象可能原因项目里看什么处理思路
速度上去后角度明显滞后 Kp/Ki 偏低或 LPF 滞后太大 pllError 长期同号，rawAngle 比 PLL 更靠前 增大 PLL 带宽，或调相位补偿
速度估计毛刺多 PLL 带宽太高或反电势噪声大 smoSpeed、pllError 抖动 降低 PLL 增益，增大 LPF 平滑，检查 ADC 噪声
高速直接捕获慢 PLL 从零速积分追速度 rawSpeed 已有速度但 pll.omega 爬升慢 项目已用 FOC_SMO_PLL_SPEED_FF_ALPHA 前馈缓解
反转时角度差半圈 反电势极性没有按速度方向统一 反转时 rawAngle 与期望差 π 项目用 SMO_GetElectricalDirectionSign() 处理

离散化：文章里的连续方程如何落到 MCU

理论推导通常写 di/dt，但 MCU 里没有连续时间微分， 只有每个 PWM 周期执行一次的离散更新。本项目用的是一阶欧拉积分： 当前状态加上“采样周期乘以导数”。这很直观，也很适合 20kHz 中断里的实时计算。

连续形式：di_hat/dt = (u - Rs·i_hat - e_hat - z) / Ls
离散形式：i_hat[k+1] = i_hat[k] + Ts/Ls · (u[k] - Rs·i_hat[k] - e_hat[k] - z[k]) 
invLs = 1.0f / smo->cfg.ls;
smo->iAlphaHat += smo->cfg.ts * invLs
                  * (uAlpha - smo->cfg.rs * smo->iAlphaHat
                     - smo->eAlpha - smo->zAlpha);

这也带来一个工程约束：Ts/Ls 不能太大。你的电机等效电感 Ls = 57µH，Ts = 50µs，所以 Ts/Ls ≈ 0.877， 已经是很激进的离散积分系数。低电感电机对采样延迟、电压误差和参数误差非常敏感， 这就是为什么项目里 PLL 增益、相位补偿、速度前馈都调得比较积极。

SMO 的适用边界：为什么低速一定难

参考文章的无感观测本质依赖反电势，而反电势和电角速度近似成正比。 电机静止时 ωe = 0，所以 Eα/Eβ = 0； 很低速时反电势虽然不为 0，但可能比 ADC 噪声、死区电压误差、电流采样偏置还小。 这时即使 SMO 算出了角度，也更像是噪声的方向，而不是转子真实方向。

本项目对这个问题的处理非常工程化：速度环无感启动时不直接相信 SMO， 而是进入 FOC_SENSORLESS_IF_ALIGN 和 FOC_SENSORLESS_IF_RAMP。 先用 Id 把转子对到一个已知电角度，再用固定 Iq 和虚拟角度爬坡。 等反电势幅值、PLL 速度和 PLL 误差都满足条件，才切到 FOC_SENSORLESS_IF_DONE。

交接条件包含：
I/F 虚拟速度 ≥ 1000rpm
PLL 机械速度幅值 > 500rpm
eMag > 0.15V
|pllError| < 0.35
连续满足 200 个 PWM 周期

环节基础讲法本项目做法为什么这样做

讲述顺序理论内容代码片段/变量汇报时可以强调
1 采集实际电流并转到 αβ clarke_transform() → iAlpha/iBeta SMO 的输入是定子坐标系电流，不是 dq 电流

5 积分电流观测器模型 iAlphaHat += Ts/Ls*(u - Rs*iHat - e - z) 虚拟电机模型被注入项拉向真实电机

10 PLL 误差检测 pllErr = -eAlphaFlux*cos(theta) - eBetaFlux*sin(theta) 叉积/相位误差，小误差时近似角度误差

12 补偿 LPF 相位滞后 phaseComp = atan(omega*Ts/alpha) 高速时减少估计角落后
13 输出无感角度和速度 smo->angle、smo->speed FocContorl() 下一周期用它做 Park/逆 Park

4. 无感启动、限流与调试策略

无感 FOC 最难的是低速。静止或很低速时反电势太弱，SMO 看到的几乎全是噪声。 当前代码有两套低速处理：开环模式用 Uq 生成虚拟旋转角度； 无感速度环用 I/F 启动，先对齐，再用固定电流和爬坡角度拖动，满足条件后交给 SMO/PLL。

推荐汇报结论：

无感 FOC 的本质是“先用电流模型和滑模面估计反电势，再用 PLL 从反电势锁出转子角度”。 代码层面最关键的是三件事：低速不能相信 SMO，所以需要 I/F；k_slide 必须覆盖运行反电势；闭环模式下用户给的是电流/速度目标，最终 Uq 由 PI 自动生成。
